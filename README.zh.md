# DSH Desktop（Tauri 外壳）

[English](README.md) | 中文

`apps/desktop`（Electron 壳）的 Tauri 版对照实现：用 Rust + WebView2 承载 DSH Web GUI，
由外壳负责 dsh 服务进程的生命周期。

## 它做什么

1. **定位 dsh 运行时**（回退链，第一个命中生效）：
   1. `DSH_TAURI_CMD`（+可选 `DSH_TAURI_ARGS` JSON 数组、`DSH_TAURI_CWD`）：完全自定义命令；
   2. 安装包捆绑的 `resources/cli/lib/bin.js`（见下方「捆绑运行时」），可搭配捆绑的 `resources/node/node.exe`；
   3. `DSH_CHECKOUT`：指定含 `apps/cli/lib/bin.js` 的 checkout；
   4. dev 默认：从 exe 位置向上推断 monorepo checkout；
   5. PATH 上的 `dsh`（经 `cmd.exe /C dsh web …`；注意强杀外壳只结束 cmd 包装，node 子进程可能存活——发布形态建议用 1–4）。
2. 绑定自己的固定端口（默认 `3090`，用 `DSH_TAURI_PORT` 可改），启动
   `web --no-open --port <port>`。端口被占用时在 splash 直接报错，**不会**退到随机
   端口：端口是主窗 origin 的一部分，而 `127.0.0.1` 的 cookie 不分端口——每换一个端口
   就多一条会话 cookie，且会发给所有 DSH 端口，累积到请求头超过 Node 的 16KB 上限后
   整个界面只会返回 `431`。
3. 监视子进程 stdout，捕获鉴权启动行 `dsh web: http://127.0.0.1:<port>/?token=…`（dsh web 需要 token，直接访问根路径会 401）。
4. 先显示 splash 窗口（打包内的状态页），token URL 到手后把 splash 销毁，
   以 `WebviewUrl::External(token URL)` 重建主窗口。
   这一步不能省：DSH 的会话 cookie 是 `SameSite=Strict`，从应用自身源
   （`tauri.localhost`）跳转过去会被拒收，WebView 会落在 401 页；主窗口的
   文档源必须是 host 本身，等价于浏览器直接打开那条 URL。
5. **监督线程**（对标 Electron 壳 backend-controller）：服务意外退出/启动失败时
   按 2s/5s/10s 退避自动重启，崩溃额度共 3 次。只有**稳定运行（≥60s）**的那一轮
   才归还额度，因此"就绪之后才崩"的崩溃循环同样会把额度耗尽。额度耗尽后监督线程
   **不会退出，而是暂停**：splash 与托盘 tooltip 会说明情况，托盘「重启 DSH 服务」
   恢复监督并重置额度；手动「重启服务」本身不消耗额度；用户主动退出
   （托盘退出/quit_app）不会触发自动重启。
6. 关闭主窗口 = 隐藏到托盘（与 Electron 壳一致）；托盘左键显示窗口，右键菜单为
   显示 / 开机自动启动（切换）/ 重启 DSH 服务 / 检查更新… / 退出。停 host 分两步：
   先发 Ctrl+C 让 `dsh` 走自身的有界优雅关闭，3 秒超时后再强杀；每个 host 进程都挂进
   kill-on-close 作业对象，外壳被强杀或崩溃都不会遗留 host 进程树（含 PATH 梯的
   `cmd.exe` 包装）。
7. 单实例：再次启动会聚焦已有窗口。窗口位置尺寸持久化（window-state 插件）。
8. **开机自动启动**：入口是托盘菜单「开机自动启动（切换）」（已无原生菜单栏），写入
   `HKCU\...\Run\DSH`，命令带 `--autostart`；这类启动保持托盘静默，崩溃重启也
   不弹 splash（只写日志与 tooltip）。卸载时由 `src-tauri/installer-hooks.nsh`
   删除该 Run 值，不留登录期报错残留。
9. **更新器**：托盘「检查更新…」两段式——第一次点击只报告新版本（splash 日志 +
   托盘 tooltip 提示），再次点击才下载、验签、安装并重启，且安装前先停止 host。

## 开发

前置：Rust（MSVC 工具链，已配合 VS Build Tools / WebView2）、Node + pnpm。

```sh
pnpm install            # installs @tauri-apps/cli
pnpm --filter @deepseek-ai/dsh-desktop-tauri dev
```

`dev` 会编译 Rust 后热加载 `dist/`（纯静态 splash，无需前端构建）。

单元测试：`cd src-tauri && cargo test`（端口挑选与运行时回退链）。

## 打包（Windows NSIS）

```sh
export TAURI_SIGNING_PRIVATE_KEY="$(cat keys/updater.key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
pnpm --filter @deepseek-ai/dsh-desktop-tauri build
# artifacts in src-tauri/target/release/bundle/nsis/:
#   setup.exe and setup.exe.sig (minisign); maintain latest.json yourself
#   when publishing (URL + signature + version manifest)
```

签名密钥对已生成于 `keys/updater.key`（**已 gitignore，务必离线备份**；
丢了就无法再发布可验证的更新）。公钥已写入 `tauri.conf.json` 的
`plugins.updater.pubkey`，`plugins.updater.endpoints` 已指向
`https://download.deepseek.com/dsh-desk-tauri/feeds/win-x64/latest.json`
（独立于 Electron 壳的 `dsh-desk` 前缀；首次发布后即生效，端点烧进安装
包，改动只对之后新安装/更新生效）。

## 自动更新（已端到端实测）

发布链路对标 Electron 壳（`apps/desktop/scripts/desktop-auto-update-environment.mjs`）：

```sh
node scripts/publish-updates.mjs         # stages dist-update/ (latest.json + artifacts)
node scripts/publish-updates.mjs --cos   # also uploads to COS (same env names)
```

要点：

- **端点必须 https**：updater 初始化即校验，http 配置会让应用启动直接 panic。
- 版本号**唯一来源是 `tauri.conf.json` 的 `version`**（package.json/Cargo.toml
  仅保持一致性；改错地方曾导致版本不涨）。
- 支持/测试钩子：`DSH_TAURI_UPDATE_CHECK=1` 启动，3 秒后走与托盘
  「检查更新…」相同的 检查→下载→验签→安装→(重启) 流程。
- 已知行为：NSIS 静默更新终结运行中的应用后**不会自动重启**（上游行为），
  更新完成需手动重开。实测证据：安装版 0.1.0 → feed 0.1.1 → 日志
  「发现更新 0.1.1，开始下载并安装…」→ 安装目录版本 0.1.1 → 再启动
  「当前已是最新版本」。
- 无外网端点时的 E2E 配方：自签证书（SAN 含 `IP=127.0.0.1`，装入受信任根）
  → PFX 私钥导入**本机** My 存储 → `netsh http add sslcert ipport=127.0.0.1:18443`
  → HttpListener serve `latest.json` + setup.exe → 旧版 + 钩子启动验证；
  测完删除证书与绑定。rustls 走系统证书库，`CurrentUser\Root` 即可。

## 桌面行为约定

- **无终端窗口**：`main.rs` 的 `windows_subsystem = "windows"` 让 exe 是 GUI
  子系统（漏掉它 = 每次启动自带一个黑窗，标题是 exe 路径）；launch ladder 的
  每个 spawn（node、PATH 回退的 cmd、where.exe 探测）都带 `CREATE_NO_WINDOW`。
  不要改回"给进程挂隐藏控制台"路线——实测 AllocConsole 的 conhost 窗口藏不干净。
- **无原生菜单栏**：文件/编辑/视图/窗口菜单栏已移除；全部功能在**托盘**
  （显示、开机自启切换、重启服务、检查更新、退出）。
- **登录桥接**：主窗口注入 `EXTERNAL_LINKS_JS`：页面里的 `window.open`
  （账号授权预开弹窗、帮助链接）统一转系统浏览器（`open_external` 命令 +
  opener 插件，仅允许 http(s)，按 URL 解析校验）。原生 webview 默认拒绝
  window.open，登录流程没有回退路径会直接死掉——勿删此脚本。
- **Host 页面的 IPC 属于 remote IPC**：主窗文档源就是 host，Tauri 判定为
  *remote* origin，因此该页面默认调不到任何命令。`capabilities/host-page.json`
  只给它一条命令（`allow-open-external`）且仅限回环地址；
  `capabilities/default.json` 给本地 splash 四条命令。命令权限由 `build.rs`
  自动生成到 `src-tauri/permissions/autogenerated/`（已 gitignore）。扩大 Host
  页面可调用面是安全决策，不是便利开关。
- **导航守卫**：`on_navigation` 把主窗锁在 host origin，其余跳转一律转系统浏览器
  （对标 Electron 壳的 `will-navigate`）。
- **文件拖放交给页面**：主窗用 `disable_drag_drop_handler()`，否则 Tauri 会截获
  系统文件拖放，Web GUI 的附件拖放区收不到 `drop` 事件。
- **图标**：`icon-src/icon.png` 用官方 `apps/desktop/resources/icon-windows.png`
  （鲸鱼），改图标后 `pnpm exec tauri icon icon-src/icon.png` 重新生成。

## Host 日志管道（防静默崩溃）

host 及其子进程（如 Serena MCP 的 cp936 横幅）可能输出非法 UTF-8 字节。Rust
侧读取 host stdout/stderr 必须按**字节级 pump + lossy 解码**（server.rs 的
`pump_lines`）；用 `BufReader::lines()` 一旦遇到非法序列就终止循环，管道读端
句柄被 drop，host 下一次写日志得到 EPIPE 并**静默 exit(1)**，表现为周期性
"服务意外停止"崩溃循环。已有单测 `pump_lines_survives_non_utf8…` 守住该行为。

## 闭包必须带构建环境（登录防回归）

runtime-cli 闭包是从仓库已构建的包 lib 部署出来的。**客户端 lib 必须带
`DSH_CLIENT_VERSION` 内联 define** 构建，否则账号 UI 的 `client()` 在第一次
点击登录时直接抛错（表现为"登录失败：操作未完成"，浏览器不会弹出）：

```powershell
$env:DSH_CLIENT_VERSION = (Get-Content package.json | ConvertFrom-Json).version
$env:DSH_CLIENT_COMMIT_HASH = git rev-parse HEAD   # checkouts whose .git was cleared: use the official baseline hash in LOCAL-CHANGES.txt at the repo root
pnpm run build:lib:client; pnpm run build:web
cd apps\desktop-tauri; node scripts\prepare-runtime-cli.mjs
```

`verify-runtime-cli.mjs` 会扫描闭包里的 `({}).DSH_CLIENT_VERSION`（define 缺失
的形态）并失败。DSH 更新频繁 = 这正是设计：每次 DSH 发版按上面步骤重建闭包、
`pnpm run build` 出新签名安装包、`publish:updates` 推 feed，已安装的桌面壳经
托盘"检查更新"（或 `DSH_TAURI_UPDATE_CHECK=1` 启动钩子）自动跟进。

## 运行时闭包防回归

`pnpm run verify:runtime`（`prepare:runtime` 尾部自动执行、`build` 前置执行）：
检查闭包完整性（无符号链接、web-frontend dist、workspace 依赖全解析、
app 自链接剔除）并在闭包内跑 `bin.js --version` 功能探针。空占位目录时
静默通过（回退链会接管）。

## 捆绑运行时（安装包自包含）

一键生成（需先 `pnpm install` 且 `pnpm run build` 构建过仓库产物）：

```sh
node scripts/prepare-runtime-cli.mjs   # generates runtime-cli/ and runtime-node/
pnpm exec tauri build
```

脚本做的事（细节与坑）：

1. `pnpm --filter @deepseek-ai/dsh deploy --prod --config.node-linker=hoisted --config.allowUnusedPatches=true runtime-cli`
   —— 必须 **hoisted**（平铺真实目录）：默认的 symlink 布局经打包复制后链接会断；
   `allowUnusedPatches` 是因为仓库全局 patch 集与 CLI 子集不匹配；
   新版共享 lockfile deploy 在本仓库有 bug（会漏掉 workspace-linked 的
   `dsh-web-frontend`），hoisted 老路径完整。
2. 把 deploy 残留的 workspace 符号链接实体化为真实目录（指向 vendor/packages
   的链接在装机后必然失效）。
3. 删除闭包里混入的 app 自身链接（`dsh-desktop`/`dsh-desktop-tauri`），否则会把
   整个 Rust target 拷进 bundle（曾经 9GB+）。
4. `runtime-node/node.exe`：便携 node（脚本拷贝运行它的 node，可换成官方
   win-x64 zip 里的 node.exe）。
5. `tauri.conf.json` 的 `bundle.resources` 把两者映射进包内
   `resources/cli/`、`resources/node/`；外壳按回退链优先使用它们
   （日志行 `spawned [bundled resources/cli]`）。

`runtime-cli/`、`runtime-node/` 已 gitignore；产物是纯运行时（含 office/语音/终端
等原生组件，约 520MB，安装后 ~600MB）。

## 启动配置（环境变量）

按优先级：

| 变量 | 含义 |
| --- | --- |
| `DSH_TAURI_CMD` / `DSH_TAURI_ARGS` / `DSH_TAURI_CWD` | 完全自定义启动命令（ARGS 为 JSON 数组） |
| `DSH_TAURI_NODE` | node 可执行文件路径（优先于捆绑 node 与 PATH 上的 `node`） |
| `DSH_CHECKOUT` | 指向包含 `apps/cli/lib/bin.js` 的 checkout 根目录 |
| `DSH_TAURI_PORT` | 固定 host 端口（默认 3090；被占用会报错，不会改用随机端口） |
| `DSH_TAURI_PROFILE` | host 启动的 profile（默认 `web`；`desktop` 被 Electron 壳保留，不可用） |
| `DSH_TAURI_HOME` | 为子进程设置 `DSH_HOME`：会话、日志与 task-board 账本锁都按 home 计算，与终端会话并存时需各自独立 |
| `DSH_TAURI_CWD` | host 的工作目录——会话按工作区分桶，要接上你在浏览器里用的那个项目就设成它（安装版默认用户主目录，绝不会是安装目录） |
| `DSH_TAURI_TAKEOVER` | 默认开启：启动 host 前结束当前 `DSH_HOME` 里持有 task-board 账本的 DSH host（先 Ctrl+C，超时再强杀）。设为 `0` 则不动对方，任务板留在对方 |

外壳运行日志写入 `%TEMP%\dsh-tauri.log`，同时显示在 splash 底部。每行都带 UTC
时间戳，且 `token=` 值会被脱敏（host 会打印带 token 的启动行，stdout 全部镜像到该文件）。

## 一个状态根只跑一台 host

同一个 `$DSH_HOME` 只能由一台 host 服务：任务板只有一个持有者
（`$DSH_HOME/task-board/ledger-v2.lock`），而 host 会对它打开过的每个会话持有内核写租约，
第二台 host 恢复这些会话时只会得到 `session/writer-held`。因此外壳在启动自己的 host 之前，
会结束本机上的其它 DSH host——除 session 0 以外的所有登录会话，因为抢同一个状态根的两台
host 常常不在同一个会话里：先处理账本里记录的那台（并核对启动时间，因为 PID 会被复用），
再枚举所有镜像精确等于 JS 运行时（`node.exe` 等）、命令行确实执行 `bin.js` 且带完整参数
`web`、并且属于当前账户的存活进程——账户与镜像名这两道门槛，是因为接管会强制结束进程树。脚本路径若是**绝对路径**，
必须真实存在；若是**相对路径**（从 checkout 起 host 的常见写法）则无法校验——那是对方进程的工作目录，Windows
没有廉价办法读取——这种情况只靠镜像名、路径边界和完整参数三条规则判定。每次接管的日志还会写明本次启动的来源
（冷启动 / 崩溃后重启 / 第二次启动 / 托盘重启）。每台都先 Ctrl+C，超过与自己子进程相同的宽限期才强杀，
日志逐条记下。有一个 Windows 完整性级别的限制：在管理员终端里启动的 host，对从资源管理器
启动的桌面 app 是不可见（拿不到命令行）也不可结束的，此时外壳只记 `接管受阻` 而不猜测。
让两者用同级权限启动，或者以管理员身份运行桌面 app。设 `DSH_TAURI_TAKEOVER=0` 则不动其它 host。
另需注意：已在运行的实例沿用它自己启动时的策略，
所以再启动一次客户端会聚焦那个实例并让它重新夺回状态根，随后重启自己的 host 以重新获取任务板。

## 与 Electron 壳（apps/desktop）的差异

- 运行时来源：Electron 壳捆绑自己的 primary-runtime；Tauri 壳默认复用 checkout 里的
  dsh CLI（按上节捆绑后可脱离 checkout）。
- 桌面端 Host 协议：Electron 壳经 `dsh-desktop-host` 的 stdio JSON 协议启动并握手；
  Tauri 壳走公开的 `dsh web` 启动行协议（token URL），更简单但少了 Host 业务 IPC：
  没有 shutdown 握手，外壳先发 Ctrl+C（`dsh` 自身有有界优雅关闭）再强杀，而
  Electron 壳有显式 shutdown 请求并先确认运行中的任务。
- 尚未移植：崩溃恢复弹窗、dsh 命令安装管理、账号/登录、强制更新窗口、遥测、
  macOS/Linux 打包。
