# 01 · 项目总览

## 1. 这是什么

`dsh-desktop-tauri` 是 DSH（DeepSeek Harness）的 **Tauri 桌面外壳**：一个
Rust + WebView2 的原生壳进程，负责

1. 启动并监督 DSH 的 **Host 服务进程**（`node apps/cli/lib/bin.js web …`）；
2. 把 Host 自带的 Web GUI（`http://127.0.0.1:3090`）装进原生窗口里显示；
3. 提供托盘、单实例、开机自启、窗口状态记忆、两条自动更新链（壳自身 + 内核）；
4. 提供 NSIS 安装器，把外壳挂载到机器上已有的（或新部署的）harness 检出之上。

它是 monorepo 里 Electron 外壳 `apps/desktop` 的 Tauri 对等物，行为约定尽量对齐
（差异清单见 `README.zh.md` 末节“与 Electron 壳的差异”）。

- 包名：`@deepseek-ai/dsh-desktop-tauri`（private）
- 版本单一来源：`src-tauri/tauri.conf.json` 的 `version`（当前 **0.1.22**；
  `package.json` 与 `Cargo.toml` 手工保持同值）
- 应用标识：`ai.deepseek.dsh.desktop.tauri`，产品名 `DSH`，发行方 `DeepSeek`
- 许可：MIT

## 2. 历史沿革

该目录原是 deepseek-harness monorepo 内的 `apps/desktop-tauri`，后独立为
`D:\code\DSH\dsh-desktop-tauri` 项目并自带 git 历史。独立带来的四点变化
（`README.md` / `README.zh.md` “Standalone project” 一节）：

- **构建应用本身不再依赖 monorepo**：`pnpm run build`、`tauri build`、`cargo test`
  均可在本目录独立进行；安装器默认不含运行时，而是挂载到 harness。
- **重新生成 vendored CLI 闭包**（`pnpm run prepare:runtime`）需要一个 harness
  检出，须显式 `DSH_REPO_ROOT` 指明；运行期 dev 启动梯级的 `default_checkout`
  也认这个变量（过去靠向上遍历目录找检出，独立后不再可行）。
- **发布更新**（`pnpm run publish:updates`）需要 `cos-nodejs-sdk-v5`，
  `pnpm add -D cos-nodejs-sdk-v5` 或 `DSH_REPO_ROOT` 借用 monorepo 安装。
- **README 中英双语配对检查**不再被 monorepo 的门禁覆盖；`README.i18n.yaml`
  作为记录保留，双语同步靠手工。

2026-11 起，本项目又以 **git subtree** 方式并入 `D:\code\启动器` 仓库的
`dsh-desktop-tauri/` 子目录（保留上游 9 个提交的完整历史），融合完整性核对见
[09-融合核对报告.md](09-融合核对报告.md)。

## 4. 不在版本库里的东西（.gitignore）

| 路径 | 说明 |
|---|---|
| `src-tauri/target/` | cargo 产物 |
| `node_modules/`、`dist-update/` | npm 依赖、发布暂存 |

| `runtime-cli/`、`runtime-node/`（及各 `.next/.old`） | 可选“自带运行时”构建的 vendored CLI 闭包与 node.exe |

| `src-tauri/installer-hooks.nsh` | 由 `prepare-installer-hooks.mjs` 从模板生成 |

## 5. 一句话运行方式

- 开发：`pnpm install && pnpm run dev`（需要机器上有可挂载的 harness 或设置
  `DSH_REPO_ROOT` / `DSH_CHECKOUT`，见 07）。
- 打包安装包：`pnpm run build`（产出 NSIS 安装器 + updater 产物 .sig）。
- 测试：`cd src-tauri && cargo test`（29 个测试，见 08）。

详细链路分别见 [06-构建发布与更新链.md](06-构建发布与更新链.md)。
