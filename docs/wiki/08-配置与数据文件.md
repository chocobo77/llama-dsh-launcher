# 08 配置与数据文件

两端的数据文件刻意同名同格式，可互导。Windows 写文件统一走 `WriteTextAtomic`（唯一临时名 + File.Replace 留 .bak）；Linux 走 `_atomic_write_json`（tmp + os.replace）——临时名必须唯一，固定 .tmp 的多个写者会互相抛异常静默丢保存。

## 配置文件 `LlamaDSH_Launcher_config.json`

- **路径**：默认 `~/Documents/`（Windows `SpecialFolder.Personal`）；界面「配置目录」可改，指针存 `~/.llamadsh_config_path.json` = `{"Dir": …}`。
- **顶层键**：`Profiles`（名字 → 方案字典）、`CurrentProfile`、`WindowWidth`、`WindowHeight`（宽高 ≤100 时回退 1400×950）。
- **旧格式兼容**：旧版「单方案对象」读取时自动放进 `"Default"` 方案；损坏时留底 `.corrupt-<时间戳>.bak` 再用默认。

### 单套方案（ProfileConfig）字段（22 个）

| 字段 | 含义 |
|---|---|
| `ModelPath` / `MtpPath` / `MmprojPath` / `MmprojUrl` / `NoMmprojOffload` | 模型文件（主模型 / MTP 草稿 / mmproj 视觉投影及其 URL / 不卸载 mmproj） |
| `LlamaDir` | llama.cpp 目录（变体切换即改此字段） |
| `LlamaBackend` | 后端显式选择：空=自动 / vulkan / rocm / cuda / sycl（两端同字段名） |
| `DshDir` / `DshMode` / `DshAdminMode` | DSH 目录 / 启动方式（0=编译产物，`node apps/cli/lib/bin.js` 优先、缺失回退源码 tsx；1=npx）/ 提权（Win 默认 true，Linux 默认 false） |
| `MinimizeToTray` | 关窗最小化到托盘 |
| `BoolParams` / `ValueParams` | 参数勾选状态：`{flag: true}` / `{flag: {Enabled, Value}}` |
| `CustomArgs` | 命令预览编辑模式追加的自定义参数 |
| `VramBreakerEnabled` / `VramBreakerType` / `VramBreakerValue` | 显存熔断：开关 / 类型（0=百分比、1=GB）/ 阈值（默认 90） |
| `LlamaVariants` / `ActiveLlamaVariant` | llama.cpp 变体列表 `{Name, Repo, Dir}` 与当前激活项 |
| `VramMeasuredMiB` / `VramMeasuredModel` / `VramMeasuredFp` | 显存实测缓存（模型名 + 精度指纹） |

**跨端兼容关键**：Windows `ProfileConfig` 带 `[JsonExtensionData] Extra`，未识别字段原样收下再写回——Windows 保存不会抹掉 Linux 侧写的字段。**合并语义**：读取与保存都逐方案以 `default_profile()` 打底；请求带部分 profile 字段是合并而非替换；不带 profile 的写操作绝不以空对象覆盖当前方案。

## 状态与辅助文件

| 文件 | 内容 | 读写方 |
|---|---|---|
| `~/.dsh_launcher_state.json` | `{LlamaPid, DshPid, DshDir}` 跨启动接管状态；`update_state` 合并写防抹键 | 两端启动时 `LoadState`/`takeover_on_boot` 接管，退出/进程结束时更新 |

| `~/.llamadsh/params_override.yml` | 用户参数表差异覆盖层（第三层加载） | 手工编辑 |

## 日志目录 `~/.dsh_launcher_logs/`

| 文件 | 内容 |
|---|---|
| `run.log` | 运行流水：逐行 `[yyyy-MM-dd HH:mm:ss] [LEVEL] 内容`；环形缓冲 2000 条 + 攒 200 行或 5s 增量落盘 |
| `info.log` / `error.log` / `crash.log` | 常规信息 / 错误 / 未处理异常（App 三重兜底与 Linux 收尾都写这里） |
| `agent.json` | `{"port","token","enabled"}`（0600；Windows 额外收紧 DACL + Hidden） |
| `*.log.1/.2/.3` | 单文件超 4MB 滚动出的历史，保留 3 份 |

要点：
- **脱敏三形态**（`?token=` / JSON token / Bearer）→ `‹已隐藏›`，写日志前先过 `Redact`；启动时 `ScrubExisting` 把历史日志（含滚动份）**按字节**重写清洗——按字节是因为文本 round-trip 会把非法 UTF-8（GBK 子进程输出/截断多字节）永久变 U+FFFD。
- **游标语义**：`seq` 从 1 起、每轮启动重置；`boot = 时间戳-PID` 标识本轮；`/api/logs` 响应带 `boot/ring/seq_first_available/gap`，客户端 boot 变了必须归零游标。
- `BuildDiagnostics`（「复制诊断」）从文件末尾倒读最多 128KB 取 40 行，不为几十行读整文件。

## 参数表 `llama_params.yml`

真源：`LlamaDSH_Launcher_CS/Resources/llama_params.yml`（2638 行，同时嵌入 exe）；Linux 内置副本 `webui/llama_params_default.yml`。三层加载：内置 → exe/程序旁（缺失自动提取；schema 版本更高则自动升级并备份 .bak）→ `~/.llamadsh/params_override.yml` 差异覆盖（只写非空字段：aliases/offValue/offFlag/wide/enabled/advanced/hidden/deprecated）。

```yaml
meta:
  schema: 12            # 版本号单调递增驱动自动升级
  adapt: ...            # 对齐的 llama-server build（0.7.0-dev b11680）
  notes: ...            # 维护手册：对齐方法、aliases 迁移、role 保留等 11 条
groups:
  - {id: model, title: 模型与加载, order: 0}   # 共 7 组
params:
  - flag: ctx-size
    role: ctx_size       # 语义角色（13 个），内部逻辑按 role 取值
    label: 上下文长度
    type: int            # string | bool | combo
    default: 4096
    group: model
    subgroup: ...        # 组内小节
    wide: true           # 输入框占整行
    advanced: false      # 归入高级折叠区
    requires:            # 前置条件（op 白名单：enabled/disabled/==/!=/>/</>=/<=）
      - {flag: XXX, op: enabled}
    conflicts: [...]     # 互斥
    implies: [...]       # 连带
    offValue: ...        # 关闭语义：显式发射关闭值
    offFlag: ...         # 关闭语义：显式发射关闭 flag
    validate:
      min: 0
      max: 1000000
      leq: other-flag   # 值不得大于另一参数
      regex: "..."
    aliases: ["ctx_size"]  # 旧 flag 名迁移
    tooltip: ...
```

加载后统一校验（`$cpu` token 展开、flag 去重、坏引用删规则降级、正则预编译、组排序），**只降级不抛**。规则引擎口径：前置未满足的参数**整条不参与命令行**（连 offValue/offFlag 关闭语义也不发射）——这是头号回归约束，两端同款。

升级 llama.cpp 后的维护动作：把新版 `llama-server --help` 存成文件与参数表逐条 diff，改完点「重载参数配置」（Windows）/「schema/reload」（Linux）当场生效，无需重启。

## 显存预估口径（概要）

`Peak ≈ 权重×0.95 + KV缓存 + 计算图缓冲 + 固定开销 + mmproj + 草稿模型`

- KV 按**全注意力层数**折算（手写 GGUF 解析取 layers/kv_heads/head_dim/SWA/SSM），混合架构不会把线性注意力层当全注意力算；FA 关闭且 V 缓存未量化时回退 f16。
- 计算图 ≈ ubatch × embed × 173B；运行时基线 300MiB（CUDA context 120~550MiB、mmproj-offload +1136MiB、MTP 内置 +668MiB / 外部草稿 +1413MiB）。
- `fits` 三态：True / False / **None（探针读不到显存，≠装得下）**。
- 逐项公式与实测校准见仓库根 `显存占用计算指南.md`（不入库）。
