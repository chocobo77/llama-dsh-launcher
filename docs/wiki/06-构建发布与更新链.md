# 06 · 构建、发布与更新链

## 1. 前置

- Rust MSVC 工具链（VS Build Tools）、WebView2（缺则安装器
  `downloadBootstrapper` 现下载）、Node + pnpm。
- 开发运行还需要一个可挂载的 harness（`DSH_REPO_ROOT`/`DSH_CHECKOUT`），
  否则启动梯级只能指望 PATH 上的 `dsh`。

## 2. 开发

```bash
pnpm install                 # 装 @tauri-apps/cli
pnpm run dev                 # = prepare-installer-hooks + tauri dev
```
（README 里写的 `pnpm --filter …` 是 monorepo 时代的形态；独立后直接
`pnpm run dev`。）

## 3. 构建安装包（含更新签名）

```bash
export TAURI_SIGNING_PRIVATE_KEY="$(cat keys/updater.key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
pnpm run build               # = prepare-installer-hooks + tauri build
```

产物：`src-tauri/target/release/bundle/nsis/DSH_<ver>_x64-setup.exe` 与同名
`.sig`（minisign）。`createUpdaterArtifacts: true` 所以 .sig 必产。
- **`keys/updater.key` 是私钥：.gitignore 排除，绝不入库**；公钥已硬编码进
  `tauri.conf.json`（两者配对，换钥要同步改 conf）。私钥须脱机备份——丢了
  就无法给旧安装壳发布可信更新。
- 版本单一来源 `tauri.conf.json`；`package.json`、`Cargo.toml` 手工同值。

## 4. 可选：自带运行时（self-contained）

默认安装包**不带运行时**（挂载到 harness）。要回到自包含形态：

```bash
DSH_REPO_ROOT=<monorepo检出> pnpm run prepare:runtime   # 尾部自动 verify:runtime
```

制备 `runtime-cli/ + runtime-node/`（见 05 §2），`tauri build` 会把它们作为
资源打包，setup 阶段 `set_bundled_cli/node` 生效（梯级第 2 级）。
日常回归：`pnpm run verify:runtime`（默认 build 已**不再**前置跑它，因为
默认包不带运行时）。闭包必须带 `DSH_CLIENT_VERSION` define（05 §3 第 7 项）。

## 5. 发布更新 feed

```bash
pnpm add -D cos-nodejs-sdk-v5    # 独立项目后自带依赖，或借 DSH_REPO_ROOT
node scripts/publish-updates.mjs --env test --cos   # 或 production
```

- test 环境需 `DOWNLOAD_TEST_ORIGIN`（https）+ `DOWNLOAD_TEST_RELEASE_ID`；
  production 固定官方 origin + `DOWNLOAD_PROD_COS_*` 三件套。
- staging 在 `dist-update/`：setup.exe、.sig、`latest.json`
  （`platforms.windows-x86_64: {signature, url}`）。
- 上传顺序（05 §4）：产物（forbid-overwrite）→ .sig → feed。
- feed 地址：`https://download.deepseek.com/dsh-desk-tauri/feeds/win-x64/latest.json`；
  客户端可用 `DSH_TAURI_UPDATE_ENDPOINT` 覆盖（逗号列表，逐个尝试）。

## 6. 端到端更新验证（README 配方）

在测试机上真跑一遍“旧壳发现新壳→下载→安装→重启”：

1. 自签证书 **SAN 必须含 IP=127.0.0.1**（仅 CN 不行）；生成 PFX；
2. 导入**本机** My 存储；
3. `netsh http add sslcert ipport=127.0.0.1:18443 certhash=… appid=…`；
4. 用 HttpListener（或任何 https 服务）在 `https://127.0.0.1:18443/...`
   serve `latest.json` + setup.exe（版本号高于已装、包用同一私钥签）；
5. 旧壳设 `DSH_TAURI_UPDATE_ENDPOINT=https://127.0.0.1:18443/.../latest.json`
   启动，走托盘“检查更新”完成全链。

## 7. 图标

母图 `icon-src/icon.png`；改图后 `pnpm run icon`
（= `tauri icon icon-src/icon.png`）重新生成 `src-tauri/icons/` 全套
（桌面 + android/ios，78 个受控文件里一大半是图标）。

## 8. 两条更新链的运维视角

| | 壳自更新（updater） | 内核更新（harness_update） |
|---|---|---|
| 载体 | NSIS setup.exe + minisign .sig + latest.json | git 浅同步到最新 `dsh-v*` tag |
| 触发 | 托盘 / `--check-update` / `DSH_TAURI_UPDATE_CHECK` | 托盘 / `--check-harness-update` |
| 失败面 | 404/超时/签名不符 → `explain_update_error` 人话 | 阶段 0/2/4 语义（04 §7）：绝不带病重启 |
| 互斥 | 共享 `UPDATE_IN_FLIGHT`/`UpdateSlot`，同时只允许一条链在途 | 同左 |

## 9. 与启动器仓库（D:\code\启动器）的联动

本项目以 git subtree 并入启动器仓库 `dsh-desktop-tauri/`；启动器的
`一键封包.cmd`（GBK/cp936，勿用 UTF-8 编辑器存盘）第 [9/8] 步会进本子目录
跑构建链并把安装包纳入发布产物。核对详见
[09-融合核对报告.md](09-融合核对报告.md)。
