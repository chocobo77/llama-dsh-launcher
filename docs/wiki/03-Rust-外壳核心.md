# 03 · Rust 外壳核心（src-tauri/src）

四个文件：`main.rs`（入口）、`build.rs`（构建期 ACL）、`server.rs`（Host 子进程
管理）、`lib.rs`（窗口/托盘/监督/命令/更新）。行号以 0.1.22 为准。

## 1. main.rs（11 行）

- `#![cfg_attr(all(not(debug_assertions), target_os = "windows"), windows_subsystem = "windows")]`：
  不加这个，整个 exe 是 console 子系统，每次启动 Windows 会分配一个可见终端
  窗口（标题为 exe 路径）——桌面壳绝不能有的东西。
- `main()` 只调 `dsh_desktop_tauri_lib::run()`。

## 2. build.rs（20 行）

`tauri_build::try_build` + `AppManifest::commands(&["server_status",
"restart_server_cmd", "check_update_cmd", "quit_app", "open_external"])`。
为什么必须有：main 窗口加载的是 **remote IPC origin**（Host 自己的 origin），
不声明 ACL 清单该 origin 就够不着任何命令；声明后 tauri-build 在
`permissions/autogenerated/` 生成 `allow-<command>` 权限，capabilities 再按窗口
逐个授予（见 02 §3）。

## 3. server.rs（2127 行）—— Host 子进程管理

### 3.1 常量

| 常量 | 值 | 含义 |
|---|---|---|
| `DEFAULT_PORT` | 3090 | 固定端口（cookie/窗口状态按 origin 记账，漂移会分裂登录态） |
| `LOG_CAP` | 300 | 环形日志保留行数（splash 显示） |
| `RING_LINE_MAX` | 2000 | 单行截断长度 |
| `GRACEFUL_EXIT_TIMEOUT` | 3s | Ctrl+C 后等待优雅退出的上限 |
| `HELPER_TIMEOUT` | 3s | 辅助进程（taskkill/where.exe 等）超时 |
| `ENUMERATION_TIMEOUT` | 5s | CIM 进程枚举超时 |
| `START_TIME_TOLERANCE_MS` | 120_000 | 进程创建时间匹配容差（PID 复用防护） |

### 3.2 `ServerState`（全局状态，Arc<Mutex>）

字段 15 个：`child`（Option<Child>）、`url`（已发布的 Host origin）、`error`、
`exit_code`、`spawning`（bool）、`port`、`log`（Vec<String> 环形）、
`quit_requested`、`generation`（代际计数）、`resume_requested`、
`recent_children`（(pid, 创建时间) 清单，接管佐证，上限 8）、`spawn_reason`、
`restart_requested`、`restarts`（已用额度）。`lib.rs` 的 `server_status`
命令把它快照成 camelCase JSON。

### 3.3 日志基础设施

- `log_line`/`push_log`：所有外壳事件同时进环形缓冲和 `%TEMP%\dsh-tauri.log`；
  行带 UTC 时间戳（`utc_stamp` + 手写的 `civil_from_days` 日期换算，不引 chrono）。
- `redact_secrets`：`token=`/`key=` 等参数值替换为 `***`——日志会进 UI 和文件，
  登录 token 绝不入日志。
- `shorten`：按字符边界截断（非 ASCII 安全）。

### 3.4 资源与 node 发现

- `BUNDLED_CLI`/`BUNDLED_NODE`（OnceLock）+ `set_bundled_cli/node`：setup 阶段
  若随包资源存在 `cli\lib\bin.js`、`node\node.exe` 就登记。
- `node_program()`：node 解析顺序 `DSH_TAURI_NODE` → bundled → PATH 的 node.exe。
- `node_for_checkout(checkout)`：优先 `<checkout>\node\node.exe`（部署脚本随
  harness 自带的 Node），否则回退 `node_program()`。
- `default_checkout()`：`DSH_REPO_ROOT` → 从 exe 位置向上走 8 级找带
  `apps\cli\lib\bin.js` 的检出（独立项目后主要靠前者）。

### 3.5 启动梯级与参数

- `launch_plan()`：六级梯级（02 §7 顺序）。要点：`DSH_TAURI_CMD` 的
  `DSH_TAURI_ARGS` 必须是 JSON 字符串数组；`DSH_CHECKOUT` 指到却没有 bin.js 是
  **硬错误**（防止配置打错后悄悄用了别的内核）；末两级探测 PATH 上的 `dsh`。
  测试 `launch_plan_ladder_order` 用合成的假检出钉住梯级顺序。
- `web_args(port)`：`["web"…profile, "--no-open", "--port", N]`。
- `workspace_override/default_workspace`：子进程工作目录 = `DSH_TAURI_CWD`，
  否则 `USERPROFILE`。绝不默认落在安装目录——会话按 workspace 分桶，装在
  安装目录里起壳会显示一个几乎空白的会话列表。
- `home_override`：`DSH_TAURI_HOME` 注入为子进程的 `DSH_HOME`（状态根：会话、
  日志、任务板锁 `$DSH_HOME/task-board/ledger-v2.lock`）。任务板**每个 home
  单持有者**——桌面壳要和终端会话并存就必须给它单独的 home，只换 profile
  解不开这把锁。

### 3.6 进程识别（接管的安全边界）

- `ProcRow`：CIM 一行（pid/名称/命令行/会话/创建时间）。
- `list_session_processes()`：`Get-CimInstance Win32_Process` 经 PowerShell helper
  输出 JSON；只取 `SessionId ≠ 0`（不碰服务会话）；UTF-8 读取。
- `is_dsh_host_row()`：两道门必须同时过——image 恰好是
  `node.exe/bun.exe/deno.exe`，且命令行含真正的 `bin.js … web`。
- `dsh_host_script(cmdline)`：在命令行里找 `apps/cli/lib/bin.js` 边界
  （`\\?\`、`//?/` 前缀展平、`d:` 盘相对 vs `d:/` vs UNC、`:`/`;` 分隔的
  环境变量转储判 NotAPath）；`web` 必须是**独立整参数**。
  测试：`drive_relative_and_device_path_shapes_are_classified_consistently`、
  `a_relative_host_command_line_is_still_a_host`、
  `the_script_gate_and_the_image_gate_both_have_to_pass`。
- `parse_board_lock()`：解析 `$DSH_HOME/task-board/ledger-v2.lock` 的
  `{"pid","token","startedAt","probe"}`，取持有者 PID 与启动时间。

### 3.7 端口

`pick_port(preferred)`：首选空闲就用；被占则**不换端口重试**（宁失败不漂移，
02 §4）。测试各钉一头：`pick_port_uses_the_preferred_port_when_free`、
`pick_port_refuses_to_drift_when_preferred_is_busy`。

### 3.8 生命周期

- `spawn_server(reason)`：
  - 全程持 child 锁 spawn；成功后 **generation→url 两个锁在同一临界区**里
    更新（防“旧泵把死 URL 发布回来”；锁序 generation→url 固定，历史上
    0.1.7 因锁序死锁卡死，注释留案）。
  - 创建旗标 `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`：无窗口且 Ctrl+C
    可定向到组。
  - spawn 途中收到 quit/restart 标志的处理（不丢事件）；watchdog 400ms 起
    监控循环按 generation 校验。
- `stop_server()`：两阶段——先 Ctrl+C 组（优雅），`GRACEFUL_EXIT_TIMEOUT`
  超时再强杀树；**等待期间释放状态锁**（UI 不冻结）；若有 spawn 在途则置
  `restart_requested` 交接。
- `pump_lines(reader, generation)`：逐行泵 Host stdout/stderr。
  **字节级 lossy 解码**，绝不用 `BufReader::lines()` 直读——历史上非法 UTF-8
  使 lines() 报错、泵线程退出、管道满导致 Host 静默 `exit(1)` 崩溃循环；
  该回归由 `pump_lines_survives_non_utf8_and_still_marks_ready` 钉住。
  每次读前检查 generation，过期泵立即停（`stale_pump_stops_reading_once_superseded`）；
  单行超 1MB 截到 64K+标记。
- `emit_pumped_line()`：剥 `dsh web: ` 前缀；识别 `ready: <url>` 行，在
  generation+url 锁下**只发布一次**（第一个 URL 占位，
  `the_first_url_published_by_a_pump_keeps_the_slot`；
  `pump_lines_ignores_ready_from_a_previous_generation` 钉住代际门）。

### 3.9 win mod —— Windows 进程机制

- `KILL_JOB`：kill-on-close Job Object，句柄**永不关闭**（外壳死了子进程必死，
  任何持句柄的线程都不例外）；辅助进程也装自己的 job。
- `alive()` 三态 Live/Dead/Unknown（查询失败不武断）。
- `send_ctrl_c(pid)`：给**整个进程组**发 Ctrl+C。手法：`AttachConsole` 到目标
  控制台 → 持全局 `CONSOLE_LOCK`（同进程内只允许一次 attach 把戏）→
  `SetConsoleCtrlHandler(NULL, TRUE)` 屏蔽自身 → `GenerateConsoleCtrlEvent`
  以组 PID 为目标 → detach。attach 失败码 1000+GetLastError 记入诊断。
  测试 `ctrl_c_is_delivered_to_the_targets_group_only`（opt-in，需
  `DSH_TEST_CTRL_C=1`，见 08）。
- `force_kill_tree(pid)`：`taskkill /T /F`；**动手前重新读进程创建时间**与
  记录值比对（`START_TIME_TOLERANCE_MS` 容差），防 PID 复用误杀无辜。
- `run_helper()`：跑短命辅助进程（PowerShell/CIM/taskkill/where.exe），
  kill-on-close job + `HELPER_TIMEOUT`。
- `own_pids()`：由 recent_children 的父→子闭包不动点扩展出“自家全部 PID”。
- `process_owners()`：`GetOwner` 逐进程查属主；**属主不是当前账户的进程永不
  动手**。
- `retire_other_hosts()`：接管主流程（02 §6 阶梯）；`recent_children` 用完即
  清（防陈旧 PID 被复用后当“自家孩子”豁免——注释留案）；board lock 缺失/
  不可读会记日志走枚举路；活着的持有者被权限挡住时报“接管受阻”；
  陈旧 owner（进程已不在）跳过 lock 直接枚举；命令行近似但不是 host 的
  进程会打 near-miss 日志帮助排障。
- `retake_state_root(app)`：接管入口。绝不内联在窗口过程里；独立线程 +
  全局 `TAKING_OVER` 防重入 Guard（Drop 释放）。

## 4. lib.rs（1197 行）—— 壳主体

### 4.1 常量与标志

`MAX_AUTO_RESTARTS=3`、`BACKOFF_SECS=[2,5,10]`、`STARTUP_TIMEOUT_SECS=120`、
`STABLE_SECS=60`；`HIDDEN_START`（`--autostart`/`--hidden` 判定）、
`FIRST_MAIN`（首启才 center()，之后听 window-state）。

### 4.2 状态快照与额度

- `ServerStatus`（camelCase serde）+ snapshot：把 ServerState 翻译成
  UI 协议，派生 `state ∈ ready|error|exited|spawning|idle`。
- `wait_for_url(timeout)`：supervise 等 `ready:` 发布（上限 120s）。
- `spent_after_run(runtime)`：运行 <60s 记消耗（“起来又死”计费），≥60s 偿还；
  `backoff_for(spent)` 查 [2,5,10]。测试
  `crash_budget_is_spent_by_short_runs_and_repaid_by_a_stable_one`。

### 4.3 窗口

- `window_size()`：默认 1280×860。
- `create_main_window(app, url)`：`WebviewUrl::External(url)`；导航守卫放行
  `about:`/`blob:`/host origin 同源（`same_origin`），其余转浏览器（测试
  `navigation_guard_accepts_only_the_host_origin_and_inline_schemes`）；
  `disable_drag_drop_handler`；注入 `EXTERNAL_LINKS_JS`（见下）；销毁 splash。
- `EXTERNAL_LINKS_JS`：`window.__dshExternalLinks` 幂等标记；覆写
  `window.open`；对 about:blank 弹窗桩的 `location.href` 赋值/replace/assign
  设访问器拦截 → 一律走 `open_external` IPC。
- `create_splash_window`：本地 `index.html`（App），标题栏无装饰差异、600ms
  轮询协议见 05 §splash。
- `user_visible_windows`：判断是否还有可见窗口（退出策略用）。
- `open_http/open_external`：解析 URL，scheme 只放行 http(s)，交
  tauri-plugin-opener 到系统浏览器。

### 4.4 托盘

`TRAY: OnceLock<…>`；`build_tray`：菜单 = 显示主界面 / 开机自动启动（勾）/
重启服务 / 检查内核更新 / 检查更新 / 退出；左键单击=显示。`tray_notice`：
气泡通知（更新结果、额度耗尽等）。

### 4.5 run()

组装插件（02 §2.2）；`setup`：解析随包资源→splash/隐藏→supervise 线程→
`DSH_TAURI_UPDATE_CHECK` 或首启 `--check-*`；`RunEvent::CloseRequested` →
**隐藏而非退出**；`RunEvent::Exit` → `quit_requested + stop_server`。

### 4.6 supervise 循环

```
loop:
  spawn_server(reason)
  若 hidden 启动 → 起来即 ready 也不弹 main（等 tray 显示）
  wait_for_url(120s)
    超时/启动失败 → 按额度退避或暂停
  轮询子进程直到退出；记录 runtime
  intentional（自然退出且非错误）→ 退出循环（跟着退出）
  runtime ≥ 60s → 偿还额度
  额度 > 3 → 暂停：splash 说明 + tray_notice + 等 resume/quit
  否则 sleep(backoff) 继续
```

`manual_restart`：stop_server → 清额度 → resume_requested；splash 若在则
show+reload。`request_quit`：置 quit_requested、stop、app.exit。

### 4.7 更新链（壳 + 内核的 UI 侧）

- `UPDATE_IN_FLIGHT: AtomicBool` + `UpdateSlot`（RAII）：两条更新链共享的
  在途锁，拿不到就提示“更新已在进行”。
- `check_harness_update`：`harness_root()`（= default_checkout）为 None →
  明确提示无挂载内核；`check()` 出 `Info`；`needs_init` → 引导确认框；
  已是最新但 `verify_local_changes("source")` 失败 → 产生**显式补丁丢失警告**
  （不因为“没更新”就跳过体检）；对话框文案引用阶段 0/2/4 语义；随后
  `sync(reuse_fetch=true)` 复用刚才 check 的 FETCH_HEAD。
- `apply_harness_update`：先 `stop_server`；`asserted = has_patch_verifier()
  && !skip_local_patches()`；`replay = asserted || local_patches_dir 存在`
  （两者分开的理由：检出缺校验脚本 ≠ 缺补丁，不能让缺脚本顺手关掉重放）；
  阶段0 仅告警 → sync/bootstrap 失败 → `manual_restart` + 通知“已用原产物恢复”；
  阶段2 restore 后 source 再验失败 → **不重建**，恢复旧产物，提示人工修锚点；
  重建失败 → 服务保持停机（不带病重启）；阶段4 build 断言失败 → 同样保持
  停机；成功 → tray_notice + `handle.restart()`。
- `explain_update_error`：404/超时/解码错误映射成人话。
- `updater_from()`：`DSH_TAURI_UPDATE_ENDPOINT`（逗号列表）覆盖 conf 里的端点。
- `check_update(interactive)`：异步查壳更新；交互式弹“下载并安装”，
  headless（--check-update 二次启动）直接装。`install_update`：先 stop_server
  再 `download_and_install`，装完重启。
- `toggle_autostart`、`show_app`（没有窗口时兜底建 splash）。

### 4.8 命令层（5 个）

| 命令 | 授予窗口 | 语义 |
|---|---|---|
| `server_status` | splash | ServerState 快照 JSON |
| `restart_server_cmd` | splash | manual_restart |
| `check_update_cmd` | splash | 交互式查壳更新 |
| `quit_app` | splash | request_quit |
| `open_external` | main（remote origin） | 系统浏览器打开 http(s) 链接 |

## 5. 贯穿性陷阱备忘（代码注释里的案底）

- 泵线程绝不直接 `lines()`（EPIPE 崩溃循环案，3.8）。
- 锁序恒 generation→url，同一临界区成对更新（0.1.7 死锁案，3.8）。
- 杀任何进程前重新核验创建时间（PID 复用案，3.9）。
- Job 句柄永不关闭（“外壳已死”语义，3.9）。
- 端口宁失败不漂移（登录态分裂案，3.7）。
