# 01 项目总览

## 项目定位

LlamaDSH 启动器面向本地部署 DeepSeek Harness（下称 DSH）+ llama.cpp 的用户，把两条工具链的日常操作集中到一个界面：

1. **参数管理**：llama-server 参数按官方 help 分组呈现，勾选即发射；参数间的依赖/互斥由规则引擎把关，违反的参数会被剔除出命令行并说明原因。一套参数存一个「方案」（profile），下拉即切换。
2. **进程控制**：llama-server 与 DSH 的启动/停止/接管（外部已在跑的进程也认领），DSH 支持编译产物/源码/npx 三种启动方式自动回退。
3. **环境维护**：Node 24 + pnpm 一键安装（验签 + SHA-256 双门）、llama.cpp 预编译包按显卡后端一键更新、DSH git 更新（带镜像与 stash 保护）。
4. **DSH 兼容修复**：bundle 激活表、失效补丁、死依赖、node_modules 悬空链接的审计与修复；插件级管理含版本豁免（对抗 DSH 频繁更新导致的插件过期）。
5. **监测保护**：CPU/内存/GPU/显存/温度采样，llama TPS/首 token 延迟统计，显存熔断（超过阈值自动停 llama，保护整机）。
6. **自动化接口**：本机 HTTP 控制面 + `llamadsh-cli` 控制台工具，供脚本/agent 调用。

MIT 许可（`LICENSE`），作者 chocobo77。

## 双端形态

| | Windows 端 | Linux 端 |
|---|---|---|
| 目录 | `LlamaDSH_Launcher_CS/` | `LlamaDSH_Launcher_Linux/` |
| 技术栈 | .NET 8 WPF（+ WinForms 仅托盘） | Python 3 标准库 + WebUI（GTK/WebKit 窗口，可降级纯浏览器） |
| 规模 | ~3 万行（MainWindow.xaml.cs 单文件 1.1 万行） | ~1.7 万行（selftest.py 占 5 千行） |
| 主界面 | 原生 WPF | WebUI（HTTP 服务 + 浏览器渲染） |
| GPU 采集 | NVML / LibreHardwareMonitor / gputemp 子进程 | /proc + nvidia-smi / amd-smi / xpu-smi / sysfs |
| Agent 端口 | 17325 | 8788（被占顺延） |
| 运行状态 | 主力维护 | 功能对齐、实验性质（Linux 端 README 自述） |

两端的关键设计刻意保持同名同语义：配置文件 `LlamaDSH_Launcher_config.json`（PascalCase 字段，可互导）、参数表 `llama_params.yml`、Agent 接口端点命名（差异清单见 [07](07-Agent-API与CLI.md)）、日志目录 `~/.dsh_launcher_logs/`、DSH 身份三层判定、显存熔断语义、轻量化三档采样。

## 文件入库分类（.gitignore 口径）

- **入库**：两端源码、`docs/API-CONTRACT.md`、`docs/安装模式与提权门控-2026-11-10.md`、`assets/`、`LICENSE`、打包脚本与 iss。
- **明确不入库**：`LlamaDSH_Launcher_config.json`（含本机路径）、`signtool-config.inc` 与一切 `*.pfx`、`installer_output/`、`installer_staging/`、`LlamaDSH_Launcher_CS/gputemp/*.exe|*.sys`、`vendor/`、`显存占用计算指南.md`、`docs/` 其余审查记录、`_verify/_test/_u5.py/_ggml_h.txt`、`pack_run.log`。
- **行尾规则**（`.gitattributes`）：`.cs/.xaml/.csproj/.iss/.cmd` 强制 CRLF（cmd.exe 解析 LF-only 脚本会吃字符）；`.md/.sh/.py` 强制 LF（CRLF 让 bash 报 bad interpreter）。

## 术语表

| 术语 | 含义 |
|---|---|
| DSH | DeepSeek Harness，node 编写的本地 Harness（源码目录含 `apps/cli`，Web 默认端口 3080） |
| llama / llama-server | llama.cpp 的 HTTP 服务端，二进制名 `llama-server(.exe)`，默认端口 8080/8081/1234 自动发现 |
| 方案（profile） | 一套模型路径 + 参数勾选 + 运行选项，存于配置 JSON 的 `Profiles` 字典 |
| 参数表 / schema | `llama_params.yml`，声明每个 llama-server 参数的 flag、类型、分组、依赖规则；内置版本号 `meta.schema: 12` 驱动自动升级 |
| Role | 参数的语义角色绑定（`ctx_size`/`ngl`/`spec_type`/`port`…），内部逻辑按 Role 取值而非硬编码 flag |
| 后端（backend） | llama.cpp 预编译包的加速 API 选型：vulkan / rocm / cuda / sycl；自动口径 NVIDIA→CUDA、Intel→SYCL、AMD→Vulkan |
| 变体（variant） | llama.cpp 目录的多版本管理（`LlamaVariants` + `ActiveLlamaVariant`，切换即改 `LlamaDir`） |
| 接管 | 启动器启动时认领外部已在运行的 llama / DSH 进程；DSH 认领需过三层身份判定（进程名→命令行→HTTP 指纹） |
| 熔断 | 显存占用超阈值即自动停 llama 的整机保护，全速监测降频时仍生效 |
| 轻量化模式 | 后台低频保活：有服务 30s 采样、无服务 60s 纯休眠、正常 3s |
| 血统（lineage） | 安装器/提权遗留的进程环境问题：Windows 用 `__COMPAT_LAYER` 判定 + 一次性 marker 封顶自重启；Linux 用 `SUDO_USER` 检测 + `execvp` 切回真实用户 |
| agent 接口 | 启动器内置的本机 HTTP 控制面（Windows 17325 / Linux 8788），`agent.json` 记录发现信息 |
| BootId / boot | 日志游标的本轮启动标识，客户端据此发现「启动器已重启、seq 游标失效」 |

## 版本

- 版本真源：`LlamaDSH_Launcher_CS/installer.iss` 的 `#define MyAppVersion`（当前 1.1.3）；`一键封包.cmd [1/8]` 把同一个 x.y.z 同步进 csproj 的 `Version/AssemblyVersion/FileVersion`，不同步则 exe 属性和 `cli status` 报的版本会停留在旧值。
- csproj、iss、`InstallScope.cs`（卸载键 GUID）、`LineageGuard`（marker）之间的常量一致性由 `selftest.ps1` §C 静态断言把关。
