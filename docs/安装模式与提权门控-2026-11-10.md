# 安装模式（仅自己 / 所有用户）与「以管理员身份启动」的门控

日期：2026-11-10。适用：Windows 版启动器（`LlamaDSH_Launcher_CS`，安装包 `installer.iss`）。
Linux 版没有安装程序这一层，本文那条链不涉及它（Linux 侧的提权仍是 `sudo` 预检那套）。

## 1. 需求

安装包运行时要让用户二选一：

- **仅为自己安装**：不开 UAC，默认装到当前用户目录（按市面用户级软件的常见位置）。
- **为所有用户安装**：需要 UAC 提权，默认装到 **D:\Program Files**（不存在就直接创建）。

并且这两种安装方式要对应到程序界面里 **「以管理员身份启动」** 复选框的行为差别。

## 2. 两种安装方式对照

| | 仅为自己安装 | 为所有用户安装 |
|---|---|---|
| 向导默认档 | **是**（`PrivilegesRequired=lowest`） | 选它时 Setup 自动重启为提权实例（过一次 UAC） |
| 默认目录 | `%LocalAppData%\Programs\LlamaDSH_Launcher` | `D:\Program Files\LlamaDSH_Launcher` |
| D 盘不可用时 | —— | 退回 `%ProgramFiles%\LlamaDSH_Launcher` |
| 谁能用 | 仅当前账户 | 本机所有账户 |
| 卸载注册表 | `HKCU\...\Uninstall\{AppId}_is1` | `HKLM\...\Uninstall\{AppId}_is1` |
| 快捷方式 | 当前用户的开始菜单/桌面 | 全体用户的开始菜单/桌面 |
| 程序文件可否被普通用户改写 | **能**（用户自己目录） | 不能（ACL 保护） |
| 「以管理员身份启动」 | 可勾，但提权必须过 UAC 确认 | 可勾，是否静默由系统 UAC 设置决定 |

命令行覆盖（无人值守/排障用，`PrivilegesRequiredOverridesAllowed=... commandline`）：
`Setup.exe /CURRENTUSER` / `Setup.exe /ALLUSERS`。

### 2.1 为什么用户级默认是 `%LocalAppData%\Programs`

VS Code、Inno Setup 自己「仅为当前用户安装」都落在 `%LocalAppData%\Programs\<应用>`。
Inno 的 `{userpf}` 就是这个值，所以脚本里用它而不是硬编码路径。

### 2.2 机器级为什么优先 D 盘

模型权重、DSH 依赖、构建产物都在这台机器的 D 盘（本机实测 `D:\` 剩余 ~288 GB）。装进系统盘的
`Program Files` 会把 C 盘挤爆，`D:\Program Files` 不存在时**直接创建**（按需求），只有两种情况例外：
**没有 D 盘**、或 **D 盘不是本机固定盘**（`GetDriveTypeW != 3`：U 盘 / 网络盘 / 光驱上建
`Program Files` 是帮倒忙）。空间不足不作为否决条件。

## 3. 程序怎么知道自己是哪种装法

安装程序在 `ssPostInstall` 往安装目录写 `install-scope.txt`（纯 ASCII，逐行 `key=value`）：

```
scope=user
dir=C:\Users\<user>\AppData\Local\Programs\LlamaDSH_Launcher
installedAt=2026-11-10 21:59:56
written-by=installer.iss
note=scope is user (per-user install) or machine (all-users install).
note2=if this file is missing the program falls back to the uninstall registry keys.
```

> 掺中文会出问题：Inno 的 `SaveStringToFile` 落的是 ANSI 字节，换台机器代码页就成乱码，
> 而这个文件是要被程序逐行解析的，所以内容保持 ASCII。

程序侧 `Services\InstallScope.cs` 按三级判定，拿不到标记也不会崩：

1. **标记文件** `install-scope.txt`（值不认识就不瞎猜，继续往下判）。`dir=` 现在**会被校验**：
   与当前运行目录不符（整个安装目录被复制到别处时标记会跟着跑）就不采用这条标记，落到下一级，
   并把原因写进日志（`MarkerNote`）。以前照单全收，会拿"另一处装的"方式给现在这份定性，
   而用户级/机器级的安全含义正好相反。
2. **卸载注册表**：`HKLM` → machine、`HKCU` → user，但**必须** `InstallLocation` 与当前运行目录
   一致才算数（残留的旧键不能拿来判现在这份）；
3. **兜底按 machine**：开发环境直接跑 `bin\` 目录、或旧安装包没有标记文件时，维持原有体验，
   不因为"认不出来"就改变用户已经习惯的行为。`Summary` 里会把判定依据写出来。

> 但**界面上的安全语气不由这三级的结论决定**（2026-11-11 起）：落到兜底的恰恰全是
> "exe 当前用户可写"的场景（直接跑 bin 目录、把安装目录整体复制到别处、标记丢失且注册表
> `InstallLocation` 不匹配），按安装方式推断就会在这些场景宣称"exe 被 ACL 保护"。
> 安全语气改由实测决定，见 §4。

启动日志一行，事后不用猜是谁判的：

```
[安装] 方式=仅为自己安装｜目录=C:\Users\...\Programs\LlamaDSH_Launcher｜判定依据=标记文件
[安装] 提示: 本机还有一份「为所有用户安装」装在 D:\Program Files\LlamaDSH_Launcher ; 两种方式互不覆盖，卸载列表里会各有一条。
```

## 4. 与「以管理员身份启动」的关系

这个复选框（`ChkDshAdmin` → `ProfileConfig.DshAdminMode`）提权的是 **DSH 子进程**
（`ShellExecute verb="runas"`，为高完整性，能读游戏进程内存；WMI 分离启动那条路提不了权）。

**两种安装方式都能勾**（已确认的选择），差别在安全前提与是否静默，提示必须跟着变。

2026-11-11 起，提示的两个来源都是**实测**，不再从"安装方式"推断（推断会在兜底/复制目录时
说出反过来的话）：

- `InstallScope.InstallDirWritable`：在 exe 所在目录试建一个临时文件（随即删除）——能不能在
  **原地替换 exe** 由目录级权限（CREATE/DELETE）决定。探测本身失败按"可写"处理，不给安全承诺。
  只探目录不探 exe 文件本身：正在运行的 exe 以 `GENERIC_WRITE` 打开必然共享冲突，拿它判
  "不可写"会得出相反的错误结论。
- `InstallScope.UacFact` / `UacLikelySilent`：读 `HKLM\...\Policies\System` 的 `EnableLUA` 与
  `ConsentPromptBehaviorAdmin`，把"本机提权是静默通过还是弹确认"写成事实；读不到按"会弹确认"处理。
  以前写死的"机器级=静默提权无 UAC 弹窗""用户级=会弹 UAC 确认"都是只对本机成立的断言
  （内置管理员 / `EnableLUA=0` 的机器上行为相反）。

于是 tooltip 与启动日志的话术变成：

```
实测：程序目录**当前用户可改写** → 这份 exe 可以被原地替换，替它开管理员令牌等于给「能改文件的人」开提权通道；提权前请在确认窗口里核对程序路径。
本机提权行为：EnableLUA=1 且 ConsentPromptBehaviorAdmin=0：提权静默通过，不弹确认
（注意：这两条同时成立意味着「任何能改这个目录的人都能静默拿到管理员令牌」，建议改用「为所有用户安装」或收紧该目录权限。）
```

「目录可写 + 本机提权静默」这种组合会在启动时额外打一条 WARN（`ApplyAdminModeScopeHint`），
不再等到出事才发现。`ProfileConfig.DshAdminMode` 的默认值（`true`）没动，两种安装方式都一样。

## 5. 两份并存的处理

用户级卸载项在 HKCU、机器级在 HKLM，两边互相看不见，装两次就是两份独立安装。

- **安装期**：`PrepareToInstall` 里 `WarnOtherScopeInstall` 在点"安装"之后、复制文件之前弹一次
  **是/否** 确认（含对面那份的路径）：选「否」直接中止本次安装，用户可以回去改选另一种方式或先卸载
  另一份；选「是」才继续（有意共存的人能继续）。放在 .NET 自动下载之前，免得等几十 MB 下载完才发现
  装成了两份。文案与按钮必须自洽——早期版本用 `MB_OK` 却写"请点取消"，而 `MB_OK` 只有确定一个钮，
  等于把提示里说的操作删掉了。
- **运行期**：`InstallScope.OtherScopeRoot` 找到对面那份就记一条 WARN（见 §3）。

> 测试这条提醒时的坑：Inno 的 `/SUPPRESSMSGBOXES` **不屏蔽 `[Code]` 里的 MsgBox**（只屏蔽 Setup 自己的
> 对话框）。所以在还留着另一份安装的机器上反复跑测试安装包，会把这条提醒一次次弹到用户屏幕上。
> 要无人值守地验证，看 setup log 里 `检测到另一种安装方式已装过: <路径>` 这行，而不是靠弹窗。

> 两处 AppId 必须同步：`[Setup] AppId={{A7F8B3C4-...}` 与 `[Code] UNINST_SUBKEY`、
> `Services\InstallScope.cs` 里的 `UninstallSubKey` 是同一个 GUID（那边 `{{` 转义，这边明文 + `_is1`）。
> 只改一处，跨安装方式的检测就看不见对面那一份。

## 7. 本次实测验证（构建机 2026-11-10）

用同一份 `[Code]` 生成隔离测试包（自己的 AppId、占位载荷、无快捷方式）跑真实安装/卸载：

- 用户级档 `/CURRENTUSER /VERYSILENT` → 落到 `C:\Users\Administrator\AppData\Local\Programs\LlamaDSH_Launcher`，
  未提权；卸载项只写 **HKCU**，HKLM 未动；`install-scope.txt` 内容见 §3（297 字节、非 ASCII 字节 0）；
  `unins000.exe /VERYSILENT` 后安装目录与 HKCU 键都干净移除。
- 同一份日志里 `adminDefault=D:\Program Files\LlamaDSH_Launcher` → 机器级默认目录与
  `LocalFixedDrive(D:\)` 判定正确（本机 D 盘为固定盘）。
- `InstallScope` 判定逻辑 4 例 12 断言全过：无标记→兜底 machine；`scope=user` 标记→user 且
  `OtherScopeRoot` 正确指出本机 `D:\Program Files\LlamaDSH_Launcher`；标记值非法→不瞎猜、退回下一级；
  仅 HKCU 卸载项 `InstallLocation` 匹配→user。
- `ISCC installer.iss` → 0 错误；`dotnet build -c Debug` → 0 警告 0 错误。

过程中被这套实测抓出来的四个真错（写进这里免得再犯）：

1. ISPP 把**行首**（缩进后第一个非空字符）为 `#` 的行当预处理器指令 —— Pascal 续行不能以 `#13#10` 开头。
2. `WizardDirValue` 是**只读**的，要改安装目录只能改内置目录页的编辑框（而 `SelectDirPage` 在这个版本
   并非全局可见）→ 放弃改页面上的文字，把提示挪到 `PrepareToInstall`。
3. `GetDateTimeString` 的第 2/3 个参数是**日期/时间分隔符（Char，不能传空串）**，不是"引号"：
   传 `'"'` 会得到 `2026"11"10`，传 `''` 直接 Type Mismatch（被 `except` 吞成"标记文件莫名不见了"）。
4. 跨安装方式提醒的按钮与文案自相矛盾（`MB_OK` + "请点取消"），已改为 是/否 且选「否」真的中止。
   另外验证方式本身有代价：`/SUPPRESSMSGBOXES` 不屏蔽 `[Code]` 的 MsgBox，导致测试包在这台还留着
   旧机器级安装的机器上把提醒**连着弹到了用户屏幕上**（2026-11-10 实测发生，已停手并确认清场：
   测试包用的独立 AppId、载荷是占位文件、装到 `%LocalAppData%\Programs` 的测试实例均已卸载，
   HKCU 测试键与临时目录已删，`D:\Program Files\LlamaDSH_Launcher` 那份真实安装未被触碰）。
   以后验证这条只看 setup log，不再靠弹窗。

## 8. 事故：用户级安装后"无限反复启动本软件"（2026-11-10，另一台机器实测）

**现象**：换机器测「仅为自己安装」，装完启动后程序被反复拉起，界面一闪接一闪停不下来。

**根因**（`App.xaml.cs` 的"安装器血统切断"，与安装方式改动叠加引爆）：那段代码的判定是

```csharp
bool installerSpawn = !string.IsNullOrEmpty(compatLayer);   // ① 非空即认为有安装器血统
if (installerSpawn || elevated) { /* 经 explorer.exe 重启自己 */ }   // ② 没有任何封顶
```

- ①「仅为自己安装」(`PrivilegesRequired=lowest`) 下 Setup 会给子进程挂 `__COMPAT_LAYER=RunAsInvoker`。
  它既不提权也不影响 WMI，本来不需要切血统，却被 ① 判成"有血统" → 每次装完都要走一遍自重启。
- ② 自重启**一次都不许超过**的前提是"重启后的实例判定不再成立"。这个前提**依机器**：explorer
  是否把子进程的令牌滤成非提权，取决于该机器的 UAC 配置（内置管理员账户 / `EnableLUA=0` /
  shell 本身就是提权时，`IsInRole(Administrator)` 永远为真）。前提一破，`elevated` 分支就每次都
  成立 → 无限拉起。

**实测依据**（无窗口探针 `WinExe`，屏幕上不出现任何东西；计数安全阀 5/8 次）：

| 场景 | 结果 |
|---|---|
| 本机：`__COMPAT_LAYER=RunAsInvoker` 的父进程 → explorer 重启 | 子进程 `compat=-`、`elevated=False` → 变量与提权都没跨跳活下来（所以本机不复现） |
| 本机：`explorer.exe "<exe>" 附加参数` | **子进程根本没被拉起来**（四个场景都只有 1 个实例） |
| 本机：`explorer.exe "<exe>"`（不带参数） | 子进程正常出现 |
| 模拟"子进程仍判定成立"的机器 + **旧语义** | **5 个实例**，被探针的保险阀掐停 —— 真机上就是无限循环 |
| 同样条件 + **新语义（标记封顶）** | **2 个实例**：重启一次后 `封顶生效, 不再自启` |

**修复**（三处，互为保险）：

1. `installer.iss` 的 `[Run]` 加 `runasoriginaluser`：装完自动启动走"原始用户"链接令牌。
   **更正（2026-11-11 实测）**：它只换令牌，**不改继承的环境块**，挡不住 `__COMPAT_LAYER`。
   当天 09:38 机器级安装完自动启动的那一份，日志里仍是
   `installer/elevated lineage detected (compat=ElevateCreateProcess, elevated=False)` ——
   也就是说真正起作用的只有下面两条（白名单 + 封顶），这条只挡住了"继承提权"。
2. `App.xaml.cs` 判定改**白名单**：只认 `Elevate*` / `InstallMonitorWritableFiles` 这类真正会改
   子进程行为的兼容层值，`RunAsInvoker` 不再触发。
3. `App.xaml.cs` 自重启**一次封顶**：重启前往标记文件写 UTC 时间戳，窗口内已有标记就不再重启
   （日志会写 `…s 内已重置过，不再自启`），无论判定是什么都直接正常启动。**自重启上限从此与
   机器 UAC 配置无关。**
   2026-11-11 加固：标记从 `%TEMP%` 移到 `%LOCALAPPDATA%\LlamaDSH_Launcher\`（本机 `%TEMP%` 被
   重定向到 `D:\Temp`，ACL 给「Authenticated Users: Modify」—— 多用户共享可写 + 文件名固定
   可预测 = 别人能预置它压制别人的血统重置，或做成符号链接让提权实例把文件写到别处）；TTL
   60→30 秒；被封顶放过的那次启动会主动删标记（不删就会把窗口内下一次**真正需要**切血统的启动
   也压掉）；并且 **fail-closed**：`TryMarkRelaunchAttempted` 写失败或写完回读校验不过就
   **放弃重启**（封顶是那条链上唯一的下限，写不进去还照样重启 = 缺陷原样复活且事后无从发现）。

**两个必须记住的坑**（都是这次踩的）：

- 一次性凭证**不能用命令行参数**：`explorer.exe "<exe>" --xxx` 实测不会把程序拉起来，只有不带额外
  参数的形式有效。第一版把凭证塞进参数，等于让程序装完再也不出现——是比原 bug 更糟的回归。
  跨进程传状态只能靠文件。
- 写 `DateTime.Now.ToFileTimeUtc()`、读回来用 `DateTime.UtcNow`/`FromFileTimeUtc` 比，会差出整个
  时区（UTC+8 ≈ 8 小时），标记**永远判成过期**，封顶形同不存在。写和读必须同一时间基准。

**如何确认修好了**：看 `%UserProfile%` 下启动器日志。修好后最多一条
`installer/elevated lineage detected (...)`，紧跟着若还需要重置则是
`lineage flags still present after reset ... 60s 内已重置过，不再自启`；再不会出现连续多条。

## 9. 打包

`一键封包.cmd <版本号>` 会把版本写进 `installer.iss` 再 ISCC，本次未动 `MyAppVersion`（当前 1.1.3）。
安装行为对用户可见，建议下次按 `1.2.0` 打包。

## 10. 2026-11-11 review 第二轮加固（打包与无人值守）

- **`/VERYSILENT` 不再卡弹窗**：`PrepareToInstall` 里定了一条规则——静默模式只做**硬失败检查**，
  一切信息性询问走 `AskYesNoOrAssume()`（只写日志、按"继续"处理）。原因：`[Code]` 里的 `MsgBox`
  不受 `/SUPPRESSMSGBOXES` 管辖（见 §5 的坑），而"环境检查结果…是否继续？"在HasRealGpu 的机器上
  必弹 → 无人值守安装一直等点击。缺 .NET 8 运行时在静默下改成**明确失败**并写清出路，不做
  需要管理员交互的自动下载。
- **「仅为自己安装」的真实前提写进文案**：这条路不需要管理员，但**要求本机已装好 .NET 8 Desktop
  Runtime**——运行时是机器级安装，缺它时仍需管理员（向导文案、.NET 那一问、缺它时的中止文案都
  写了这一点）。以前"两种方式都不需要管理员权限"式的说法对标准用户 + 新机器不成立。
- **打包脚本**：`[6/8]` 前不再留旧包——`[7/8]` 调 ISCC 之前先删上一轮的 `Setup.exe`，`:fail`
  会把目录里现存包的时间戳打出来并明说"本轮已中止，那是旧包，不要发布"；FAIL 行数为 0 时
  不再报"0 项未通过"，而报"测试进程异常退出"；Inno Setup 7 作为兜底参与定位（优先 6）。
- **回归测试本身**：`selftest.ps1` 的编译改成 `Start-Process + WaitForExit(超时)` 并加
  `/nodeReuse:false /p:UseSharedCompilation=false`（不加会留构建服务器进程继承重定向句柄，
  实测同一条命令从 ~5 秒变成 603 秒，打包看起来像卡在 [6/8]）；清理放进 `trap`，注册表残留算
  FAIL、临时目录删不掉只 WARN（真实用例全过时不该因此中止打包）。
- **agent 侧**：`llama/start` / `dsh/start` 改成三态回报（见 `API-CONTRACT.md` §1.2），
  请求体类型错误两端统一 **400**（§1）。用户级安装下"以管理员启动 DSH"真的会被用户在 UAC 上取消，
  以前那种"下发过就算成功"的返回把这个失败完全藏住了。
- **Linux**：sudo 血统切换移到 `lineage.py` 并在 **import 其它模块之前**执行（`applog`/`core`/`main`
  都在 import 时按 `~` 算路径，以前 root 那一轮会先建好 `/root/.dsh_launcher_logs` 并重写历史日志）；
  历史日志脱敏改按**字节**重写（文本 round-trip 会把非 UTF-8 字节换成 U+FFFD，不可恢复）；
  警告打印走 `safeout.fix_streams()`（非 UTF-8 的 stdout 上 `print("⚠")` 会把降级路径变成崩溃）。
